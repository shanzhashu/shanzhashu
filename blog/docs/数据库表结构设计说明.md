# 数据库表结构设计说明

- 数据库名：`mydata`
- 数据库引擎：MySQL 5.5+
- 默认字符集：utf8

---

## 表一：my_content（内容表）

存储用户发布的短博客内容。

| 字段名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| f_id | bigint(20) | PRIMARY KEY, AUTO_INCREMENT | 内容唯一ID |
| f_time | datetime | NOT NULL | 发布时间 |
| f_name | varchar(32) | NOT NULL | 发布者用户名（关联 my_user.f_name） |
| f_content | varchar(280) | NOT NULL | 内容正文，最长 280 字符 |

索引：
- 主键索引：`f_id`
- 普通索引：`f_time`（用于时间排序查询）
- 普通索引：`f_name`（用于按用户过滤）

字符集：utf8  
存储引擎：InnoDB

---

## 表二：my_user（用户表）

存储用户账号信息。

| 字段名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| f_id | bigint(20) | PRIMARY KEY, AUTO_INCREMENT | 用户唯一ID |
| f_name | varchar(32) | NOT NULL, UNIQUE | 用户名，全局唯一 |
| f_key | varchar(32) | NOT NULL | 用户鉴权密钥（即 session token） |
| f_email | varchar(64) | NOT NULL | 用户邮箱 |

索引：
- 主键索引：`f_id`
- 唯一索引：`f_name`

字符集：gbk  
存储引擎：InnoDB

---

## 表关系说明

`my_content.f_name` 与 `my_user.f_name` 为逻辑外键关联（未设置数据库级外键约束），每条内容记录归属于对应用户名的用户。

---

## 鉴权机制说明

系统采用基于 `f_key` 字段的 token 鉴权方式。客户端每次请求需携带 `session` 参数，服务端通过查询 `my_user` 表中匹配的 `f_key` 来验证身份，并获取对应的 `f_name` 用于后续数据操作。
